Data and AI Statement

Meiyu Prepare uses public data and local statistical-learning code to study an offline method for rainfall reference events and to explain stock-relocation preparation costs for small shops. It is not an official warning service, a shop-flood predictor, or a loss-probability product.

Current status. The project has not completed real merchant validation, measured avoided loss, demonstrated revenue impact, or demonstrated carbon reduction. No equipment was purchased, no merchant or school back-office data was connected, and no personal information was collected. Cost examples are hypothetical scenarios in CNY.

Frozen experiment and online boundary

Historical experiment

The historical experiment uses 636 paired days: 276 training, 120 validation, and 240 test days, with 18 test events. The event threshold is 25 mm of nominal UTC-day reference precipitation, a research threshold rather than an official warning level.

The AI task maps numerical-weather inputs to the event probability. The selected method is a small logistic regression using logistic_rain, with C=10 selected only on validation. Test Brier is 0.0455 for the selected model and 0.0697 for the fixed training-period event-rate baseline. A temperature/humidity comparison scored 0.0444 but was not selected. Lower Brier is better.

The model is frozen offline. It does not retrain in the browser, choose a test threshold, or create a source-free prediction. The current-weather page is a separate public forecast display, not the historical model running online.

The original continuous-rain rule and selected model share ROC-AUC 0.9712. The model adds probability expression but not new rainfall-ranking ability. Validation has three events and test has 18, so some probability bins under-estimate event frequency. The raw 25-mm rule's 0/1 squared-error score remains 0.0625.

Online weather and cache

Online weather and the frozen experiment are separate. Python cache under runtime/weather stores raw response, content hash, retrieval time, and source-specific completeness; the browser stores a local cache. Forecast older than three hours, or background/station reference older than 24 hours, is stale. Retrieval time is not initialization or provider publication time.

  • The English main app (/en/) automatically requests Hangzhou Ensemble weather and reuses a valid browser cache.
  • The English static historical demo (/en/demo.html) keeps history offline and requests Ensemble only after the user clicks refresh.
  • The original Python/Chinese research workbench (app.py) keeps its Latest weather page button-triggered and uses Forecast.

Timeouts, rate limits, wrong units, wrong station, duplicate timestamps, malformed response, and missing hourly precipitation do not replace a valid cache. A 24-hour window is not assigned a complete total when any hour is missing and is never filled with zero. Ensemble fractions are uncalibrated internal frequencies, not shop-flood or loss probabilities. Forecast API cannot be presented as ensemble.

The delivered snapshot is labeled with its actual capture time. The 2026-10-19 snapshot must not be presented as freshly updated when a page is opened offline. ERA5 and SSOD shown in the English pages are archived explanatory information, not a claim that those pages implement a complete real-time station-and-forecast service. The English main app's automatic Ensemble, the English static demo's button-triggered Ensemble, and the original workbench's button-triggered Forecast are distinct behaviors.

Reproducibility references

Frozen model and score files are reports/evaluation.json and reports/experiment_run.json. Source manifests and public snapshots remain in the repository. English materials were prepared on 2026-10-24; historical and capture dates remain unchanged.
