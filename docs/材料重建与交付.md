# 材料重建与交付

所有命令在 `meiyu` 目录运行。当前状态见[当前进度](当前进度.md)。旧 `src.materials` 命令和函数已停用，执行会明确报错，不再覆盖项目说明、验证计划或提交清单。

## 项目说明的唯一排版源

编辑 `templates/submission/参赛项目说明.html`，配图在同目录。不要只修改 `docs` 中的生成结果。该源保留四页内容、团队信息待填状态和冻结实验事实；没有训练或在线请求。

先生成HTML和Markdown，确认内容及公式，再另生成含PDF的候选版本：

```powershell
python -m src.submission --output build/说明内容检查
python -m src.submission --output build/说明PDF检查 --pdf --font C:/Windows/Fonts/simhei.ttf
```

PDF额外需要 `reportlab`、`pypdf`、`Pillow` 和支持中文的TTF字体；应用运行不因此增加依赖。其他系统用 `--font` 提供当地可用中文字体。本轮在Windows黑体及现有运行时验证，其他字体或系统仍需重新检查。

输出只允许写入工程 `build` 下尚不存在的独立目录；重复运行须换版本名。生成器从同一HTML源导出Markdown和PDF，记录文件摘要。完成PDF逐页渲染检查和独立审查后，将四个文件（Markdown、HTML、PDF、演示页面.png）同步到 `docs`，旧稿先另存到 `reports/internal`。其他声明、验证计划、脚本和清单为独立维护文件，不被该命令重写。

## 工程包与内部记录

```powershell
python -m src.package --root . --output dist/梅雨有数_工程_新版本.zip
```

工程包包含源码、模板、原始数据快照、冻结结果、正式候选材料及必要评估报告；根目录README指向当前状态。`build`、`dist`、`tools`、运行缓存不进入包。`reports/internal` 和 `reports/续接核验_20261015` 留在本机，保存旧稿、旧任务路径和渲染检查图，不进入工程包；原始审查记录不删除。

`reports/package_manifest.json` 由打包器重建，记录逐文件大小及SHA256。打包后需检查ZIP CRC、清单与包内字节、当前源码一致性及六个冻结摘要，再另存ZIP摘要。本次交付不替换根目录10月14日的 `handoff_manifest.json`。

ZIP是本地可复现工程候选包，不是已发布网址或已提交凭证。公开部署和报名继续按提交清单执行。

## 比赛提交材料（2026-10-18）

本轮按用户要求只整理本地材料，团队信息留空，不公开或提交。三份PDF分别为四页项目说明、两页AI声明、两页验证计划；原169秒MP4保持字节。

先在工程目录使用具备`markdown`的Python生成HTML，再使用具备PDF依赖的Python导出；候选目录必须位于build且首次生成时不存在：

```powershell
python -m src.competition_materials html --output build/比赛材料_新版本
python -m src.competition_materials pdf --output build/比赛材料_新版本 --font C:/Windows/Fonts/simhei.ttf
```

先核对HTML和公式，再导出PDF并逐页渲染检查。确认后执行`package`阶段，它会将已检查的候选文件同步至docs，并生成新的提交目录和ZIP；此阶段还需当前工作区根目录的历史冻结清单及既有用户测试ZIP：

```powershell
python -m src.competition_materials package --output build/比赛材料_新版本 --release dist/比赛提交_新版本
```

该目录只包含五项提交材料、必要补充材料和可编辑源稿。实际报名字段、公开链接与人工确认仍在提交前补齐。旧队友包、旧静态发布包不会被覆盖或冒充新版本。

若原目录旧项目说明PDF无法覆盖，生成器保留它并另存日期版本；工程打包使用独立快照，将已检查的候选说明三种格式统一放入包内。10月18日最新版路径见当前进度，不以被占用的旧同名PDF作为提交稿。

## 完整队友接手包的重建

在含根目录`handoff_manifest.json`、`AGENTS.md`及接手核验工具的工作区内，从`meiyu`运行：

```powershell
python -B tools/build_teammate_handoff.py
```

额外需要`markdown`构建依赖。此入口在临时目录制作当前工程快照，重建静态材料站，将最新用户测试ZIP、必要工具、当前接手说明和历史审查记录整合到`dist/梅雨有数_队友完整接手包_时间戳.zip`，不会覆盖旧ZIP或根目录历史清单。用户测试ZIP必须与当前七份源文档一致，否则先运行`tools/build_user_test_pack.py`重建。

完整接手包与标准工程包范围不同：完整包另附接手工具、用户测试ZIP和`site/dist`；站点分段下载中的标准工程包不重复包含这些外层接手文件。当前逐文件身份由`delivery_manifest.json`记录，旧六冻结基线原字节保留。构建过程不上传、不读取真实用户记录或账户绑定。生成后应核验ZIP、清单、静态下载重组与六冻结，进行独立审查再交付。
