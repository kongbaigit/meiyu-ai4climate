# 梅雨有数用户测试执行包

版本：UT-20261016-v1。状态：材料已准备，尚未招募或开展正式测试。约10分钟/人，计划5—8名自愿参与者。本包验证原型理解与操作，不验证天气预测效果、实际避损或市场需求。

## 使用顺序

1. 负责人阅读本页及[主持流程](02_主持人逐字稿.md)、[评分规则](04_评分与判定.md)，填好日期、保管人与退出截止日期。
2. 按[招募与参与说明](01_招募与参与说明.md)联系参与者。文案只是草稿，没有代发。
3. 团队先做一次演练，编号R01，只检查流程与计时，不计入正式用户结果。
4. 正式每人复制一份[单人记录](05_单人空白记录.md)，编号P01、P02……。只给参与者[任务卡](03_参与者任务卡.md)和演示，不给评分规则、案例答案或整个主持包。
5. 按固定顺序执行，先记录首次回答，再解释；当天整理[汇总与整改](06_结果汇总与整改.md)。

## 文件与用途

| 文件 | 使用者 / 用途 |

| 01_招募与参与说明.md | 团队复制邀请文字；主持人取得自愿同意 |

## 启动前清单

- [ ] 测试负责人、记录保管人、正式测试日期已填；团队已完成报名和公开访问安排。当前包可先供内部演练。
- [ ] 计划招募人数5—8人；优先有小商户备货、防潮或备汛相关经验的成年人。只记录相关经验“有/无/不愿回答”，不收门店身份。
- [ ] 队友/项目熟悉者只做演练；如实际参与者不符合目标用户假设，在报告中单独列出。
- [ ] 两人分工为主持和记录；只有一名主持时如实记录，不补造观察。
- [ ] 演示版本与文件摘要已抄入记录；同轮不改页面和任务，中途必须改则新建轮次，不混合计算。
- [ ] 在实际设备上确认2025-06-01和2025-07-18可选择，参考降水可揭晓；“最新天气与完整度”能展示已有缓存及来源。
- [ ] 默认不录音、录像或截取参与者屏幕；不收联系方式、门店地址、营业额、库存价值。
- [ ] 原始记录保存于工程`runtime/user-tests/UT-20261016-v1/`或团队私有目录；不要填回本包、`docs`、`site`或公开仓库。`runtime`已被现有工程打包白名单排除。
- [ ] 确认记录日期、可申请删除的截止日期与保管人。建议原始记录最多保存30天；团队必须确认能执行才向参与者承诺，到期删除不在本轮自动执行。

## 固定测试条件

数据版本`meiyu-493c58d793af9bf4`，模型版本`logistic_rain-v1-C10-cfge0631554`。主任务使用2025-06-01，漏报讨论使用2025-07-18；均为说明用途选定的历史案例，不是随机样本。

每人开始前回到“历史体验”，设置2025-06-02 08:00、准备成本10单位、参考降水收起。关闭来源折叠项，从页面顶部开始。这样主任务需要实际选择日期，避免默认日期已正确造成假完成。

本轮不点击获取最新天气，使用已有缓存识别来源、获取时刻和状态；记录实际显示内容，不改系统时间或伪造过期状态。若设备已有不同缓存，保留差异并记录，不能宣称缓存状态完全一致。因技术故障无法显示时按技术中断处理，不给参与者判错。

## 结论边界

这是带基本风险说明、可查看页面的理解测试，不是无提示记忆考试。内部演练、主持人帮忙后完成、讲解后改答均单独记录，不能当作首次独立成功。未招募、未完成及差评同样保留；没有数据时汇总写“未实施”，不得填示例人数或虚构反馈。
