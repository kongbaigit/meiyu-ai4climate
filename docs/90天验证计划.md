# 90 天验证计划

本计划是待执行方案，不是已完成调研或试点。目标用户暂定杭州需要防潮备汛的小商户；招募联系人、门店类型、人数与日期尚未确认。

## 时间安排

以团队实际确认的启动日为第1天；若2026年10月下旬启动，90天约至2027年1月下旬。该区间不包含下一轮完整梅雨期。90 天内验证产品理解、操作和真实预报获取；梅雨季预测表现留待新一季独立数据，不能用历史演示替代。

| 周期 | 要做什么 | 判断依据 |
| --- | --- | --- |
| 第 1—2 周 | 团队确认用户假设；计划招募 5—8 位自愿参与者；预先写明问题、退出方式和不收集的资料 | 是否真的需要这类准备解释；无法招募则只完成桌面评估，并明确缺少用户证据 |
| 第 3—4 周 | 用固定的历史案例完成理解测试，不让参与者承担真实天气风险 | 能否读懂概率、时间日界、非积水含义和假设成本；记录误解原话需另获同意 |
| 第 5—8 周 | 接入可核实初始化与公开可用时间的单次预报，记录获取失败和发布时间；先影子运行 | 每次预测是否在决策前取得；来源或完整小时缺失时是否停止判断 |
| 第 9—12 周 | 复查失败案例与操作记录；开展第二轮理解测试；决定继续、修改或停止 | 理解误差是否减少、用户是否愿意继续、数据是否支持更广范围；不据冬季结果承诺梅雨效果 |

## 预先登记的检查目标

以下数字是项目计划阈值，不是既有成果。小样本只作可用性探索，不用于统计推广。

- 操作：计划参与者中至少 80% 能在 3 分钟内完成选择窗口、解释成本、找到来源与揭示参考降水。
- 理解：至少 80% 能正确说明“低概率不等于安全”“降雨不是积水”“成本是情景假设”。有关键误解就先改页面。
- 技术：记录每次来源获取、解析、发布时间和缺失状态；未核实可用时刻的预测不计入实际决策回放。
- 模型：在新增独立数据中固定事件和评价规则，继续与同样本的基线比较；样本或事件不足就报告不足，不给稳定增益结论。
- 成本：只记录团队实测运行时间与接口调用，分别报告时间、内存和外部服务条款；商户准备成本与避损能力需要另行核实。

## 停止或收缩条件

无法得到同站、同窗口、可解释质量的数据时停止对应效果结论。不能核实真实预报可用时刻时保留离线演示。若使用者持续把概率当官方预警或积水结论，停止对外建议，先修订信息表达。若方法未优于可解释基线，保留基线，调整 AI 必要性的表述。

## 参与与数据

不要求后勤接入或现场布设设备。后续用户测试由团队自愿招募，先说明目的与退出方式，只记录完成情况和必要反馈；门店地址、营业额、库存价值、个人联系方式不作为默认采集项。公开原型不展示私人门店资料。

## 执行材料与计分规则

已准备UT-20261016-v1用户测试执行包，含招募文案、逐字稿、固定任务、评分规则及空白记录；尚未开展真人测试。同意且开始任务并允许保留记录者计入分母，整份撤回者删除并剔除；退出但允许保留和未撤回的技术中断计入分母，分别列出原因。独立操作成功与核心理解通过分别报告分子/分母，讲解后改答及重试不补作首次成功。具体口径以执行包为准。
